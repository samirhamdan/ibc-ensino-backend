### 2. Planos e configuração

Arquivo app/billing/plans.py com os 4 planos do PRD §6:
- Semente: R$149/mês, 50 alunos ativos, cota IA básica
- Crescimento: R$349/mês, 250 alunos ativos, cota IA padrão
- Comunidade: R$699/mês, 1000 alunos ativos, cota IA avançada
- Enterprise: sob consulta, ilimitado

Cada plano define: limite_alunos, cota_interacoes_ia_mes,
preco_mensal_brl. Planos são configuração, não banco de dados
— um dict/dataclass versionado em código.

### 3. Integração Asaas (BIL-01, BIL-02)

Criar app/billing/asaas.py com cliente HTTP para a API Asaas:
- Criar customer (tenant → customer Asaas)
- Criar subscription recorrente (mensal, Pix/boleto/cartão)
- Cancelar subscription
- Todas as chamadas com retry (3×, backoff exponencial) e
  timeout (10s) — chamadas de billing nunca podem travar
  a request do usuário; rodar via worker RQ quando possível.

Webhook handler: POST /billing/webhook/asaas
- Validar assinatura do webhook (header Asaas-Access-Token)
- Processar eventos: PAYMENT_CONFIRMED → ativo,
  PAYMENT_OVERDUE → registrar, PAYMENT_DELETED → verificar
  régua (BIL-02)
- Publicar domain event correspondente (outbox em
  domain_events) → worker processa e atualiza billing_status
- Idempotente: processar o mesmo webhook 2× não muda estado

Régua automática (BIL-02), executada pelo scheduler diário:
- D+10 sem pagamento: billing_status → 'leitura'
  (usuários do tenant podem VER mas não CRIAR/EDITAR)
- D+30 sem pagamento: billing_status → 'suspenso'
  (login bloqueado, página de suspensão por inadimplência)
- Cada transição: e-mail automático ao admin do tenant +
  linha no audit_log

Middleware de billing: adicionar ao request pipeline (APÓS o
middleware de tenant, ANTES dos blueprints de conteúdo):
verificar billing_status do tenant — 'leitura' bloqueia
mutations (POST/PUT/DELETE) retornando 402 com mensagem
clara; 'suspenso' redireciona para página de suspensão.
Exceções: /billing/*, /health, /api/theme (sempre passam).

### 4. Medição de consumo (BIL-03) — stub

Função app/billing/metering.py:
- registrar_interacao_ia(tenant_id, tokens_in, tokens_out,
  custo_estimado): insere/atualiza ai_usage do período atual
- consumo_do_tenant(tenant_id): retorna uso do mês corrente
  vs. cota do plano (0.0–1.0)
- checar_cota(tenant_id): retorna True se dentro da cota,
  False se estourou; emite domain event 'ai.cota_80pct'
  quando atingir 80% (alerta ao operador)

O módulo ai/ vai chamar essas funções — por ora são stubs
que apenas gravam no banco sem chamada real à API de IA.
